# 08 — Import Pipeline

## Purpose

Turn a filled XLSX template into a working structure, with hierarchy derived from
hierarchical numbering and every problem reported with its row number before
anything is committed. This is the primary entry path, so its error reporting
matters more than its happy path.

---

## 1. Pipeline stages

```
File
 └─▶ readWorkbook()      SheetJS → raw cell matrix
      └─▶ mapColumns()   header row → column indices (tolerant)
           └─▶ parseRows()    cells → RawRow[] + parse findings
                └─▶ groupRows()    same nomor → one node candidate
                     └─▶ buildStructure()   derive parents from nomor
                          └─▶ ImportPreview  ← user reviews here
                               └─▶ commit()   new project + tidy
```

Nothing before the last step touches the store. The preview is a pure function of
the file, which makes the whole pipeline testable against fixture spreadsheets and
means a failed import cannot leave partial state behind.

---

## 2. Template structure

Three sheets. Generated by the app so the dropdowns always match the shipped
config.

### Sheet `Struktur`

| nomor | nama | tipe | kategori | rumpun | jenjang | kebutuhan | eksisting | kode | unit_kerja | keterangan | *custom…* |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 1 | Kepala Dinas | Jabatan | Struktural | | JPT Pratama | 1 | 1 | | | | |
| 1.1 | Sekretariat | Unit | | | | | | | | | |
| 1.1.1 | Kepala Sub Bagian Umum | Jabatan | Struktural | | Pengawas | 1 | 1 | | | | |
| 1.1.2 | Analis Kepegawaian | Jabatan | Fungsional | Keahlian | Ahli Muda | 3 | 2 | | | | |
| 1.1.2 | Analis Kepegawaian | Jabatan | Fungsional | Keahlian | Ahli Pertama | 4 | 3 | | | | |

Data validation on `tipe`, `kategori`, `rumpun`, `jenjang` (source: `Referensi`).
`nomor` and `nama` are text-formatted so `1.10` doesn't become a number — Excel
turning `1.10` into `1.1` is the single most likely silent corruption in the whole
flow, and cell formatting is the only defence.

### Sheet `Referensi`

Named ranges per category and track, generated from `taxonomy.json`. Dropdowns
reference them. The `jenjang` dropdown cannot be truly dependent on the category
cell without volatile formulas, so it lists **all** levels and the import validator
catches mismatches. Attempting cascading dropdowns in a generated workbook is
fragile across Excel/LibreOffice/WPS — the validator is the more reliable guard.

### Sheet `Petunjuk`

Filling instructions and a worked example, in Indonesian. Explains the numbering
rule, that units leave figure columns empty, and that functional positions get one
row per level.

### Generator

```ts
function buildTemplateWorkbook(project?: Project): WorkBook
```

Given a project, exports its data into the template (that is the export path, doc
09 — same column spec, one function). Given nothing, produces a blank template with
one worked example row. Sharing the column spec between generation, export, and
import is what makes the round trip work.

## 3. Column mapping

Operators reorder columns, rename them slightly, and add their own. Match
tolerantly on normalized headers.

```ts
const COLUMN_ALIASES: Record<string, string[]> = {
  nomor:      ['nomor', 'no', 'no.', 'kode hirarki', 'urutan'],
  nama:       ['nama', 'nama jabatan', 'jabatan', 'nama unit'],
  tipe:       ['tipe', 'tipe node', 'jenis'],
  kategori:   ['kategori', 'kategori jabatan', 'status jabatan', 'jenis jabatan'],
  rumpun:     ['rumpun', 'rumpun jabatan'],
  jenjang:    ['jenjang', 'jenjang jabatan', 'eselon', 'kelas'],
  kebutuhan:  ['kebutuhan', 'keb', 'jumlah kebutuhan', 'abk', 'formasi'],
  eksisting:  ['eksisting', 'eks', 'existing', 'bezetting', 'terisi'],
  kode:       ['kode', 'kode jabatan'],
  unit_kerja: ['unit kerja', 'unit', 'satuan kerja'],
  keterangan: ['keterangan', 'catatan', 'ket'],
};

function mapColumns(headerRow: string[], schema: CustomAttribute[]): ColumnMap {
  const norm = headerRow.map(h => normalize(String(h ?? '')));
  const map: ColumnMap = {};

  for (const [field, aliases] of Object.entries(COLUMN_ALIASES)) {
    const i = norm.findIndex(h => aliases.includes(h));
    if (i >= 0) map[field] = i;
  }
  for (const a of schema) {
    const i = norm.findIndex(h => h === normalize(a.nama) || h === a.id);
    if (i >= 0) map.custom = { ...map.custom, [a.id]: i };
  }
  return map;
}
```

`status jabatan` and `jenis jabatan` map to `kategori` because those are the v1
brief's terms and will appear in files prepared from older documents. `eselon` maps
to `jenjang` for the same reason. Accepting historical vocabulary costs a few array
entries and prevents an entire category of confused support requests.

Missing `nomor` or `nama` is fatal — reported as *"Kolom nomor tidak ditemukan.
Header yang terbaca: …"*, listing what was actually found so the operator can see
whether the header row was misidentified.

**Header row detection:** scan the first 10 rows and pick the first where at least
three aliases match. Operators put titles and agency names above the table.

## 4. Row parsing

```ts
interface RawRow {
  rowNumber: number;                 // 1-based spreadsheet row, for findings
  nomor: string;
  nama: string;
  tipe?: string;
  kategori?: string;
  rumpun?: string;
  jenjang?: string;
  kebutuhan?: string;
  eksisting?: string;
  kode?: string;
  unitKerja?: string;
  keterangan?: string;
  custom: Record<string, string>;
}
```

Everything stays a string here. Coercion happens in `groupRows` where a failure can
be reported with a row number and the offending text.

```ts
function parseRows(matrix, map, headerIndex): { rows: RawRow[]; findings: Finding[] } {
  const rows: RawRow[] = [];
  const findings: Finding[] = [];

  for (let i = headerIndex + 1; i < matrix.length; i++) {
    const cells = matrix[i];
    if (cells.every(c => c === null || String(c).trim() === '')) continue;   // blank row

    const nomor = String(cells[map.nomor] ?? '').trim();
    const nama  = String(cells[map.nama]  ?? '').trim();
    const rowNumber = i + 1;

    if (!nomor && !nama) continue;
    if (!nomor) {
      findings.push({ code: 'IMPORT_NO_NOMOR', severity: 'error', rowNumber,
        message: `Baris ${rowNumber}: "${nama}" tidak memiliki nomor. Baris dilewati.` });
      continue;
    }
    if (!parseNomor(nomor)) {
      findings.push({ code: 'IMPORT_BAD_NOMOR', severity: 'error', rowNumber,
        message: `Baris ${rowNumber}: nomor "${nomor}" tidak valid. Gunakan format 1, 1.1, 1.1.2.` });
      continue;
    }
    rows.push({ rowNumber, nomor, nama, /* … */ });
  }
  return { rows, findings };
}
```

Every message leads with the row number, because the operator's next action is to
open Excel and go there.

### Number coercion

```ts
function coerceInt(raw: string | undefined, rowNumber: number, field: string,
                   findings: Finding[]): number {
  const s = String(raw ?? '').trim();
  if (s === '' || s === '-') return 0;

  const cleaned = s.replace(/\./g, '').replace(',', '.');   // 1.234 / 1,5 → Indonesian formats
  const n = Number(cleaned);

  if (!Number.isFinite(n)) {
    findings.push({ code: 'IMPORT_BAD_NUMBER', severity: 'error', rowNumber, field,
      message: `Baris ${rowNumber}: ${field} "${s}" bukan angka. Dianggap 0.` });
    return 0;
  }
  if (n < 0) {
    findings.push({ code: 'IMPORT_NEGATIVE', severity: 'warning', rowNumber, field,
      message: `Baris ${rowNumber}: ${field} negatif. Dianggap 0.` });
    return 0;
  }
  if (!Number.isInteger(n)) {
    findings.push({ code: 'IMPORT_NOT_INTEGER', severity: 'warning', rowNumber, field,
      message: `Baris ${rowNumber}: ${field} "${s}" dibulatkan ke ${Math.round(n)}.` });
    return Math.round(n);
  }
  return n;
}
```

Thousands separators appear because operators format columns. Failures coerce to 0
**and report** rather than aborting — one bad cell in row 60 must not discard the
other 79 rows of correct work.

## 5. Grouping and structure

### Grouping by `nomor`

```ts
function groupRows(rows: RawRow[]): { candidates: NodeCandidate[]; findings: Finding[] } {
  const groups = new Map<string, RawRow[]>();
  for (const r of rows) (groups.get(r.nomor) ?? groups.set(r.nomor, []).get(r.nomor)!).push(r);

  const candidates: NodeCandidate[] = [];
  const findings: Finding[] = [];

  for (const [nomor, group] of groups) {
    const first = group[0];

    // Same nomor with different names: almost certainly a numbering mistake,
    // not an intentional grouping.
    const names = new Set(group.map(r => r.nama.toLowerCase()));
    if (names.size > 1) {
      findings.push({ code: 'IMPORT_NOMOR_CONFLICT', severity: 'warning',
        rowNumber: first.rowNumber,
        message: `Nomor ${nomor} dipakai oleh nama berbeda (${[...names].join(', ')}). `
               + `Digabung menjadi satu node bernama "${first.nama}".` });
    }

    const tipe = resolveTipe(first.tipe) ?? inferTipe(first);
    const kategoriId = tipe === 'jabatan' ? resolveKategori(first.kategori ?? '') : undefined;

    // Rumpun is the union across the group — a position may span both tracks,
    // and each row carries only its own.
    const rumpun = unique(group.flatMap(r => resolveRumpun(r.rumpun)));

    const rincian: Rincian[] = tipe === 'unit' ? [] : group.map(r => {
      const jenjangId = r.jenjang ? resolveJenjang(kategoriId ?? '', r.jenjang) : null;
      if (r.jenjang && !jenjangId) {
        findings.push({ code: 'IMPORT_BAD_JENJANG', severity: 'warning', rowNumber: r.rowNumber,
          message: `Baris ${r.rowNumber}: jenjang "${r.jenjang}" tidak dikenal untuk kategori ini. Dikosongkan.` });
      }
      return { id: uuid(), jenjangId,
               kebutuhan: coerceInt(r.kebutuhan, r.rowNumber, 'kebutuhan', findings),
               eksisting: coerceInt(r.eksisting, r.rowNumber, 'eksisting', findings) };
    });

    // Unit rows carrying figures: report, then discard (invariant 1).
    if (tipe === 'unit' && group.some(r => num(r.kebutuhan) || num(r.eksisting))) {
      findings.push({ code: 'IMPORT_UNIT_HAS_FIGURES', severity: 'warning',
        rowNumber: first.rowNumber,
        message: `Baris ${first.rowNumber}: "${first.nama}" bertipe Unit, angkanya diabaikan `
               + `karena angka unit dihitung dari jabatan di bawahnya.` });
    }

    candidates.push({ nomor, nama: first.nama, tipe, kategoriId, rumpun, rincian,
                      kode: first.kode, unitKerja: first.unitKerja,
                      keterangan: first.keterangan, custom: first.custom,
                      rowNumbers: group.map(r => r.rowNumber) });
  }
  return { candidates, findings };
}
```

**Type inference** when `tipe` is blank — common, since operators skip columns:

```ts
function inferTipe(r: RawRow): NodeType {
  if (r.kategori || r.jenjang || num(r.kebutuhan) || num(r.eksisting)) return 'jabatan';
  const unitWords = /^(sekretariat|bidang|sub ?bidang|sub ?bagian|bagian|seksi|uptd|upt|balai)\b/i;
  if (unitWords.test(r.nama.trim())) return 'unit';
  return 'jabatan';
}
```

Inference is reported at `info` severity so the operator can see what was assumed.
Defaulting to `jabatan` is the safer error: a position wrongly typed as a unit loses
its figures, while a unit wrongly typed as a position merely adds a spurious zero
row that the readiness check flags.

### Deriving parents from `nomor`

```ts
function buildStructure(candidates: NodeCandidate[]):
    { nodes: OrgNode[]; edges: OrgEdge[]; findings: Finding[] } {
  const findings: Finding[] = [];
  const sorted = [...candidates].sort((a, b) => compareNomor(a.nomor, b.nomor));
  const byNomor = new Map(sorted.map(c => [c.nomor, c]));
  const idByNomor = new Map(sorted.map(c => [c.nomor, uuid()]));

  const nodes: OrgNode[] = sorted.map(c => ({
    id: idByNomor.get(c.nomor)!, type: c.tipe, nama: c.nama, nomor: c.nomor,
    kode: c.kode, kategoriId: c.kategoriId, rumpun: c.rumpun, rincian: c.rincian,
    unitKerja: c.unitKerja, keterangan: c.keterangan, custom: c.custom,
    position: { x: 0, y: 0 },                  // Tidy assigns real coordinates
    collapsed: false,
  }));

  const edges: OrgEdge[] = [];
  for (const c of sorted) {
    const pn = parentNomor(c.nomor);
    if (pn === null) continue;                 // top level

    if (!byNomor.has(pn)) {
      // Gap in the numbering: 1.1.1 present but 1.1 absent. Walk up to the
      // nearest existing ancestor rather than orphaning the whole branch.
      const ancestor = nearestExistingAncestor(pn, byNomor);
      findings.push({ code: 'IMPORT_PARENT_MISSING',
        severity: ancestor ? 'warning' : 'error',
        rowNumber: c.rowNumbers[0],
        message: ancestor
          ? `Nomor ${pn} tidak ada. "${c.nama}" dipasang di bawah ${ancestor.nomor} (${ancestor.nama}).`
          : `Nomor ${pn} tidak ada dan tidak ada induk pengganti. "${c.nama}" belum ditempatkan.` });
      if (ancestor) edges.push({ id: uuid(), source: idByNomor.get(ancestor.nomor)!,
                                 target: idByNomor.get(c.nomor)!, kind: 'hirarki' });
      continue;
    }
    edges.push({ id: uuid(), source: idByNomor.get(pn)!,
                 target: idByNomor.get(c.nomor)!, kind: 'hirarki' });
  }

  const roots = sorted.filter(c => parentNomor(c.nomor) === null);
  if (roots.length === 0)
    findings.push({ code: 'IMPORT_NO_ROOT', severity: 'error',
      message: 'Tidak ada baris bernomor tingkat pertama (misal "1"). Struktur tidak memiliki puncak.' });
  if (roots.length > 1)
    findings.push({ code: 'IMPORT_MULTIPLE_ROOTS', severity: 'warning',
      message: `${roots.length} nomor tingkat pertama ditemukan (${roots.map(r => r.nomor).join(', ')}). `
             + 'Satu menjadi puncak, sisanya belum ditempatkan.' });

  return { nodes, edges, findings };
}
```

The gap-walking behavior deserves emphasis: an operator who writes `1.1.1` without
a `1.1` row has made a numbering slip, not a structural statement. Attaching to the
nearest existing ancestor preserves their intent and reports the assumption.
Orphaning the entire branch would technically be more literal and practically
useless.

Cycles are impossible here — numbering-derived parentage is acyclic by
construction, since a parent's number is always strictly shorter.

## 6. JSON import

A different path: JSON is the app's own format, so it is validated rather than
interpreted.

```ts
async function importJson(file: File): Promise<ImportResult> {
  const parsed = JSON.parse(await file.text());
  const result = zProject.safeParse(migrate(parsed));     // doc 10 §4

  if (!result.success) {
    const repairable = classifyIssues(result.error.issues);
    if (repairable.allRepairable) return { project: repair(parsed, repairable), findings: … };
    return { project: null, findings: fatalFindings(result.error) };
  }

  const findings = validateProject(result.data, taxonomy);   // doc 04 §3
  return { project: result.data, findings };
}
```

Repairable versus fatal, decided by whether the document's meaning survives:

| Issue | Handling |
|---|---|
| Dangling edge | Repairable — drop it, report |
| Duplicate node id | Repairable — regenerate the later one, report |
| Cycle in edges | Repairable — drop the closing edges, report |
| Unit node with `rincian` | Repairable — clear rows, report figures discarded |
| Unknown `kategoriId`/`jenjangId` | Keep as-is, flag (doc 02 §5) |
| Missing `nodes` array | Fatal |
| Missing `position` on nodes | Repairable — zero it, run Tidy after load |
| Unparseable JSON | Fatal |

JSON import preserves `position` — that is what distinguishes it from XLSX import
and what makes it the save format.

The totals line is the most valuable element: an operator who knows their agency
needs roughly 250 positions will spot a parse failure that produced 80 instantly,
without reading a single finding.

**Download findings as CSV** matters because the fix happens in Excel, next to the
row numbers. Reading a scrollable dialog while editing in another window is worse
than having the list in a file.

the numbering was understood correctly before committing to 147 rows.

`canCommit` is false only for fatal findings (no root, unparseable, missing
required column). Errors on individual rows do not block: those rows are skipped
and reported, and importing 144 of 147 rows is better than importing none.

## 8. Commit

```ts
function commitImport(preview: ImportPreview, built: BuiltStructure) {
  const project: Project = {
    id: uuid(), schemaVersion: CURRENT_SCHEMA, configVersion: taxonomy.configVersion,
    meta: { namaOPD: '', kodeOPD: '', penyusun: '', ...guessMetaFromFilename(file.name) },
    attributeSchema: built.detectedAttributes,
    nodes: built.nodes, edges: built.edges,
    viewport: { x: 0, y: 0, zoom: 1 },
    createdAt: now(), updatedAt: now(),
  };

  projectStore.load(project);
  history.clear();                              // no undo across an import
  applyTidy({ direction: 'TB', scope: 'all' }); // XLSX carries no positions
  fitAll();
  ui.openPanel('recap');                        // the totals are the first thing to check
}
```

**Always a new project.** Merge by `nomor` is V1. The dialog states this before
commit, since history is cleared and any open project must be saved first.

`detectedAttributes` come from unrecognized columns: offer them as custom
attributes (type inferred from cell contents) rather than discarding. An operator
who added a "Golongan" column meant something by it.

Post-import: Tidy, fit, and open the recap panel. The operator's first question is
whether the totals look right; the layout is secondary.

## 9. Edge cases

**Merged cells** (an operator merges a division name across rows). SheetJS returns
the value in the first cell and `null` in the rest. Do not forward-fill silently —
report `IMPORT_MERGED_CELL` at warning and treat blanks as blank. Forward-filling
would fabricate structure.

**`1.10` collapsed to `1.1` by Excel.** Produces a duplicate-number conflict, caught
by `IMPORT_NOMOR_CONFLICT`. The finding message should mention number formatting as
a likely cause, since the operator will not suspect it.

**Leading zeros** (`01.02`). `parseNomor` handles them numerically, so `01.02` and
`1.2` are the same node. Report `IMPORT_NOMOR_NORMALIZED` at info.

**Trailing separators** (`1.1.`). Normalize by stripping, report at info.

**Two files imported in sequence.** Second replaces the first entirely, with a
warning if the first has unsaved changes.

**5,000-row file** (someone pasted the whole regional government). Warn above 800
rows that the design target is 500 nodes and performance will suffer. Do not block —
a large file that renders slowly is more useful than a refusal.

**Empty file / no data rows.** Fatal, with a message naming the sheet that was read
and the header row that was detected.

## 10. Exit criteria

- [ ] Every stage before commit is pure; unit-testable against fixture files
- [ ] Rows sharing a `nomor` merge into one node with multiple `rincian`
- [ ] `rumpun` is the union across a merged group
- [ ] Parents derived correctly for 4-level numbering
- [ ] Numbering gap attaches to nearest existing ancestor, with a warning
- [ ] Unit rows with figures have them discarded and reported
- [ ] `1.10` sorts after `1.9`, not after `1.1`
- [ ] Thousands separators and comma decimals coerce correctly
- [ ] One bad cell does not abort the import
- [ ] Column mapping accepts `status jabatan`, `bezetting`, `eselon`, `formasi`
- [ ] Header row detected below title rows
- [ ] Merged cells reported, never forward-filled
- [ ] Findings downloadable as CSV with row numbers
- [ ] Preview shows totals prominently
- [ ] `canCommit` false only on fatal findings
- [ ] Import clears history and runs Tidy
- [ ] Unrecognized columns offered as custom attributes
- [ ] JSON import preserves positions exactly
- [ ] Repairable JSON issues repaired and reported; fatal ones block with a clear
      message
